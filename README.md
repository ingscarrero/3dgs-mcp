# 3DGS MCP Server

An MCP (Model Context Protocol) server that lets Claude Desktop manage 3DGS Studio
projects via natural language — list projects, trigger training, check run status,
and generate guest access links.

This repo is a sibling to `3dgs-studio` and must be cloned alongside it:

```
parent/
├── 3dgs-studio/   ← the Next.js web app
└── 3dgs-mcp/      ← this repo
```

---

## Prerequisites

- Node.js 22+
- Podman (`brew install podman && podman machine start`)
- `3dgs-studio` running (the MCP server calls its API)
- `STUDIO_SERVICE_KEY` set in `3dgs-studio/.env.local` (auto-generated by `trainer-daemon/install.sh`)

---

## How It Works

The MCP server runs as a subprocess of Claude Desktop via **stdio transport**.
`run-container.sh` starts the MCP server in a Podman container, pipes
stdin/stdout through, and injects the necessary env vars read from
`../3dgs-studio/.env.local`.

---

## Setup

### 1. Clone (as a sibling to 3dgs-studio)

```bash
git clone https://github.com/<your-username>/3dgs-mcp.git
# Must be cloned into the same parent directory as 3dgs-studio
```

### 2. Build the container image

```bash
cd 3dgs-mcp
podman build -t 3dgs-mcp .
```

Or let `run-container.sh` build it automatically on first run.

### 3. Configure Claude Desktop

Add this to your `claude_desktop_config.json`
(`~/Library/Application Support/Claude/claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "3dgs-studio": {
      "command": "/absolute/path/to/3dgs-mcp/run-container.sh"
    }
  }
}
```

Make the script executable:
```bash
chmod +x /absolute/path/to/3dgs-mcp/run-container.sh
```

### 4. Ensure 3dgs-studio is running

The MCP server calls the studio's API using `STUDIO_SERVICE_KEY` for
authentication. The studio must be running before Claude tries to use
MCP tools.

### 5. Verify STUDIO_SERVICE_KEY is set

```bash
grep STUDIO_SERVICE_KEY ../3dgs-studio/.env.local
```

If it's missing, run `bash ../3dgs-studio/trainer-daemon/install.sh` to
generate it.

---

## Environment Variables

These are read automatically from `../3dgs-studio/.env.local` by `run-container.sh`.
You do not need to set them manually.

| Variable | Description |
|----------|-------------|
| `PROJECTS_ROOT` | Host path to projects directory → mapped to `/app/data/projects` |
| `NEXTAUTH_URL` | Studio URL → used as `STUDIO_URL` inside the container |
| `STUDIO_SERVICE_KEY` | Service key for bypassing session auth when calling the studio API |

## Development

The container builds TypeScript at startup:

```bash
# Build image
podman build -t 3dgs-mcp .

# Test interactively (MCP speaks over stdio)
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test","version":"1"}}}' \
  | bash run-container.sh
```

To rebuild after source changes:
```bash
podman build -t 3dgs-mcp .
```
